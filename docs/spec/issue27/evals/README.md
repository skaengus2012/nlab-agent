# 행동 평가 (#27)

지시문 변경 전후로 에이전트 행동이 달라지는지 확인하는 평가다. 계획은 `docs/spec/issue27/plan.md`의 "행동 평가 설계"를 따른다.

## 구성
- `scenarios.json`: 시나리오와 통과 조건(정규식). 회귀 6개(`kind: regression`)와 의도 변화 검사 1개(`kind: intent`)
- `run.sh`: `claude -p`를 시나리오마다 반복 실행한다. 끝난 실행은 건너뛰므로 재개할 수 있고, 총 비용이 `EVAL_CAP_USD`(기본 25)에 닿으면 중단한다
- `judge.py`: 정규식 판정. 결과 JSON을 읽어 시나리오별 통과/유효 횟수를 출력한다. 예산 초과 등 오류로 끝난 실행은 "무효"로 따로 센다. 한국어 응답과 오탐에 약해서 최종 판정은 아래 Opus 채점에 맡겼다
- `opus_judge.py`: 조건 라벨을 숨긴 블라인드 2차 채점기(`claude-opus-5-5`). 시나리오의 `rubric`만 보고 통과를 판정하며 결과를 캐시한다. `claude`가 잠시 사라져도 최대 10분 기다린다
- `results-raw.tsv`: Sonnet 실행별 정규식·Opus 판정과 Opus의 이유. 원본 출력은 저장소에 두지 않는다
- 원본 출력(`run-*.json`)은 저장소에 두지 않는다. 요약은 `baseline.md`, `results.md`에 기록한다

## 실행 방식과 격리
- 시나리오마다 빈 임시 디렉터리에서 실행하므로 프로젝트의 `CLAUDE.md`는 로드되지 않는다
- 지시문은 `--append-system-prompt-file`로 직접 주입한다. 이 플래그는 `claude --help`에 독립 항목으로 나오지 않고 `--bare` 설명에만 언급되는 비문서화 플래그이며, 설치된 CLI(2.1.325)에서 동작함을 확인했다
- 모델은 판정용 `claude-sonnet-5-5`, 민감도 병행용 `claude-haiku-5-5`(보고만, 재작성 트리거 아님), 두 모델 모두 `--effort medium`
- 도구는 끈다(`--tools ""`). 모든 시나리오는 단일 턴 텍스트 응답을 판정한다

## 격리 확인 결과 (2026-11-15, Haiku, 4회)
| 확인 | 결과 |
|---|---|
| 서로 다른 표식을 담은 두 사본을 주입 | 각 사본의 표식(`BLUE-1`, `RED-2`)만 답함. 격리됨 |
| 전역 `~/.claude/CLAUDE.md` 유입 | 유입됨. 응답 언어를 한국어라고 답했고, 실제 시나리오에서는 "Respond in English"를 명시해도 한국어로 응답했다(전역 규칙이 "예외 없음"). 그래서 판정 규칙은 영어와 한국어 표현을 함께 받는다 (`baseline.md`의 "판정 규칙 수정") |
| fixture `.claude/skills/` 로딩 방식 | 도구 없는 실행에서는 스킬이 로드되지 않음. 시스템 프롬프트 주입으로 고정 |
| 실행당 비용 | 격리 확인(Haiku, 짧은 프롬프트)은 약 0.0008달러였지만 실제 시나리오(Sonnet)는 전역 `CLAUDE.md` 등이 함께 로드되어 약 0.024달러다. 계획의 추정(0.08~0.15달러)보다는 낮다 |

## 한계
- 회귀 검출은 통계적 유의성이 아니라 휴리스틱이다
- 시스템 프롬프트 주입으로 전후가 모두 전부 통과하는 천장에 붙으면 회귀를 과소 검출할 수 있다
- Opus 채점도 규칙을 지켰는지만 보며 응답 품질은 판정하지 않는다. 정규식 판정은 형태 위반은 잘 잡지만 한국어 응답에 약하다
- `description` 트리거와 도구를 쓰는 다단계 행동은 평가하지 않는다
- Fable은 한도와 비용 때문에 돌리지 않았으므로 "가장 최신 모델에서도 같다"는 직접 증거는 없다
