## 배경 및 문제
code review skill이 리뷰 코멘트 초안을 작성할 때, 유사한 코멘트가 이미 존재하는지(예: 같은 PR에 이전에 게시된 리뷰 코멘트) 확인하지 않는다. 그 결과 중복되거나 불필요한 피드백이 게시될 수 있다.

## 목표
- 초안 코멘트가 기존 코멘트와 유사하면 게시하지 않고 보류한다.
- 중복 검사를 어느 시점에 수행해야 하는지 판단하고 그 근거를 문서화한다.

## 범위
### 포함
- 초안 코멘트와 기존 코멘트의 중복 검사 동작 정의
- 중복 검사 시점 2곳(검토/검증 단계, GitHub 게시 직전)의 평가 및 필요 여부 결정, 근거 문서화
- "유사"의 기준 정의
- 대상 스킬: `requesting-code-review` (사용자 확인)
- 검사 시점 결정 근거는 `docs/spec/issue29/` 아래 별도 문서로 남김 (사용자 확인)
- 중복 비교 대상: 같은 PR의 이전 리뷰 코멘트 (사용자 확인)
- 보류된 코멘트는 사용자에게 보류 사실과 사유를 알림 (사용자 확인)

### 제외
- `receiving-code-review` 스킬 (사용자 확인)
- 일반 PR 코멘트, 이슈 코멘트 등 같은 PR의 이전 리뷰 코멘트 외의 비교 대상 (사용자 확인)

## 기능 요구사항
| ID | 요구사항 | 출처 |
|----|----------|------|
| FR-1 | 초안 리뷰 코멘트가 기존 코멘트와 유사하면, 게시하지 않고 보류한다. | 본문 (Needs) |
| FR-2 | 중복 검사를 (1) 초안 코멘트를 검토/검증하는 시점, (2) 리뷰를 GitHub에 실제 게시하기 직전 시점, 두 곳에서 수행하는 방안을 평가한다. | 본문 (Needs) |
| FR-3 | 두 검사 시점이 모두 필요한지, 하나로 충분한지 결정하고 그 근거를 문서화한다. | 본문 (Needs) |
| FR-4 | "유사"의 정의를 정한다 (예: 같은 파일/라인 범위 + 비슷한 내용). | 본문 (Needs) |

## 인수 기준
- [ ] 초안 코멘트가 기존 코멘트와 유사할 때 게시되지 않고 보류된다.
- [ ] 두 검사 시점에 대한 평가 결과와, 둘 다 필요한지 하나면 충분한지에 대한 결정 및 근거가 문서화되어 있다.
- [ ] "유사"의 기준(파일/라인 범위, 내용 유사성 등)이 정의되어 있다.

## 영향 범위
- `skills/requesting-code-review/SKILL.md` — "Reviewer Guidelines" 섹션이 리뷰어의 코멘트 작성·게시 기준(`gh api` 라인 단위 코멘트, 정확한 라인 앵커링)을 정의하고 있어 이슈의 "code review skill"에 해당하는 것으로 보임. 현재 중복 확인 관련 내용은 없음.
- `skills/receiving-code-review/SKILL.md` — 리뷰 수신 측 스킬이며 이번 작업 대상이 아님 (사용자 확인).
